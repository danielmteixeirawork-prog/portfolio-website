EMS Discovery

A Windows desktop tool that finds EMS controllers (Raspberry Pi) on a local network and backs up their MariaDB/MySQL databases.

  • Sole developer
  • C# / .NET 10
  • WPF (XAML)
  • async/await
  • MySqlConnector
  • Single-file self-contained

TL;DR — A WPF desktop app on .NET 10 for field technicians. It automatically detects Raspberry Pi devices on the local network (ARP table, parallel ping sweep, and vendor MAC filtering) and exports those devices' MariaDB databases to .sql, with live progress and cancellation. Shipped as a single executable with no dependencies to install.

Overview

A support tool for on-site installation and maintenance. The technician joins the customer's network, hits "Start Scan", and sees the controllers that were found. From there they can open the device's web interface or connect to its database and pull a backup — without installing anything else.

Stack

Language / UI C# / .NET 10, WPF (XAML) with custom styles
Networking System.Net.NetworkInformation (ping, interfaces), reverse DNS, ARP table parsing
Database MySqlConnector (MariaDB / MySQL)
Distribution dotnet publish self-contained, single-file for win-x64

Architecture

MainWindow (WPF / XAML)
   │  async/await · CancellationToken · IProgress<T> · Dispatcher marshalling
   │
   ├─▶ NetworkDiscoveryService ──┬─▶ ArpService    read + parse the system ARP table
   │                             ├─▶ PingService   sweep, ≤50 concurrent (SemaphoreSlim)
   │                             └─▶ reverse DNS + Raspberry Pi OUI match
   │
   └─▶ DatabaseService ──▶ MySqlConnector ──▶ MariaDB on the device ──▶ .sql file

A deliberately small structure: the UI (MainWindow) holds no network or database logic, and each service does one job — which is what makes the whole thing cancellable and testable by hand in the field.

Features

Scanner tab

  • Two-phase discovery: first an immediate read of the system ARP table, so already-known devices appear at once; then a full sweep of every active IPv4 subnet — detecting the interfaces, deriving the network and prefix from the mask, and skipping networks larger than /16.
  • Parallel sweep with up to 50 concurrent pings (SemaphoreSlim) and cancellation at any point.
  • Vendor identification: the MAC of every responding IP is matched against Raspberry Pi OUI prefixes, and the hostname is resolved by reverse DNS.
  • A live, duplicate-free list (IP, MAC, hostname, state, last seen). Double-clicking a row opens the device's web interface.

Database tab

  • Connects to MariaDB/MySQL with the host pre-filled from the discovered device.
  • Lists the databases, excluding system schemas.
  • A .sql backup writer built from scratch: SHOW CREATE TABLE plus per-table INSERTs, with correct value escaping (binaries as hex, dates, numbers in invariant culture) and FOREIGN_KEY_CHECKS disabled during restore.
  • Per-table progress bar, cancellation (the incomplete file is deleted), and a timestamped log.

Technical highlights

50concurrent pings
2phase discovery
1file, zero install
  • Fully asynchronous (async/await, CancellationToken, IProgress<T>) so the UI never blocks during a sweep or a backup.
  • Network service events marshalled onto the UI thread through the Dispatcher, with an INotifyPropertyChanged model so device states update live.
  • ARP table parsing that handles both the Windows and the Linux output formats.
  • Clean split between the UI (MainWindow) and the services (NetworkDiscoveryService, ArpService, PingService, DatabaseService).
