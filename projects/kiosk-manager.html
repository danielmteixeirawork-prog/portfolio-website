Kiosk Manager

Fleet device management for the physical kiosk boards that display EMS dashboards on-site — discover them, provision them, and administer them remotely, from Windows, Linux or macOS.

  • Sole developer
  • .NET 10
  • Avalonia UI
  • MVVM
  • Python agent
  • SSH.NET
  • Cross-platform

TL;DR — A cross-platform Avalonia desktop client on .NET 10, paired with a dependency-free Python agent running as a root systemd unit on each board. Management deliberately happens over a bearer-token REST API instead of SSH, because the boards ship with a shared unprivileged factory login. Boards are found by UDP broadcast or by CIDR scan, and the provisioning scripts are embedded in the executable so a technician needs nothing but the binary.

Overview

Kiosk Manager is a separate application with its own git repository and its own release cycle. It discovers and remotely administers the physical kiosk display boards that run EMS dashboards on-site: Debian 11 ARM64 Rockchip single-board computers running a fullscreen Chromium kiosk.

Why it is two pieces

Management deliberately does not happen over SSH. The boards' SSH account is a shared, unprivileged factory-default login that cannot touch network configuration, the certificate store, or the kiosk config file. So the design splits in two: 

KioskManager.App   (Avalonia · Windows / Linux / macOS)
      │
      ├─ discovery ──┬─ UDP broadcast              instant, local L2 segment only
      │              └─ CIDR scan + SSH identity   works across routed subnets
      │
      ├─ provisioning (one time only) ──SSH / SCP──▶ board
      │      embedded resources: setup-kiosk.sh · install-agent.sh · kiosk_agent.py
      │
      └─ management (everything else) ──HTTP + bearer token──▶ kiosk_agent.py
                                                                 (root systemd unit)
                                                                  ├─ status
                                                                  ├─ kiosk URL / cert / network
                                                                  └─ reboot · refresh ·
                                                                     clear cache · shutdown

board: Debian 11 ARM64 (Rockchip SBC) ─▶ fullscreen Chromium ─▶ EMS dashboard
  • board-agent/kiosk_agent.py — a dependency-free Python HTTP service running as a root systemd unit on each board, exposing a bearer-token-authenticated REST API for status, kiosk URL / certificate / network configuration, and remote commands (reboot, browser refresh, cache clear, shutdown).
  • KioskManager.App — the desktop client. Every read and write against a board goes through that HTTP API; SSH is used only for the one-time provisioning flow.

Tech stack

Desktop client .NET 10 with Avalonia UI (cross-platform XAML), Fluent theme — verified end to end on Linux, Windows and macOS
Pattern CommunityToolkit.Mvvm — ViewModels, commands, observable properties
Provisioning SSH.NET for the SSH/SCP first-time flow
Board agent Python, standard library only, running as a root systemd unit
Distribution Self-contained single-file dotnet publish for linux-x64 and win-x64, shipped as GitHub Releases rather than committed binaries

Technical highlights

  • Two independent discovery methods: a UDP broadcast — the same idea as Hikvision's SADP tool: instant, but limited to the local L2 segment — and a CIDR-range scan with an SSH identity check, which works across routed subnets.
  • Provisioning scripts embedded as resources in the compiled executable rather than referenced from disk, so a technician can run a self-contained build against a brand-new board without the source tree present.
  • Least privilege by design: rather than hand out a privileged SSH account, the narrow set of operations that genuinely need root is exposed through one authenticated API surface on the board.
  • No runtime to install on the administrator's machine — single-file self-contained builds for both Linux and Windows.
