Overview

MMS Platform is a DCIM (Data Center Infrastructure Management) platform. It brings three concerns into one system:

  • Real-time monitoring of critical infrastructure: sites, equipment, sensors, readings and alarms.
  • Physical security: access control, intrusion panels, and CCTV with PTZ and playback.
  • Oversight and administration: dashboards, video walls, scheduled PDF reports, users and per-site permissions.

The project replaces a legacy product built on ASP.NET Core MVC, Razor, jQuery and MySQL with a modern architecture: a React SPA, a .NET 10 API, background services, and a time-series database. It also ships the tooling needed to migrate the real production data off the old system.

Stack

Frontend React 19, TypeScript, Vite 8, Tailwind CSS 4, TanStack Query, React Router 7, Chart.js, SignalR client, Vitest + Testing Library
Backend C# / ASP.NET Core (.NET 10) with Minimal APIs, EF Core (mapping only), Npgsql, SignalR, Serilog

Architecture

React SPA ──HTTP/SignalR──▶ Mms.Api (IIS)
                               │
                               ▼
                     PostgreSQL + TimescaleDB ◀── Mms.Worker (Windows Service)
                               ▲                  alarms · notifications · reports · weekly plans
                               │
             Collectors (SNMP, Modbus, Hikvision…) via Mms.Collector.Sdk
  • Clean Architecture across separate projects: Core (pure, testable domain rules), Infrastructure, Security, Api, Worker, Migrator and Collector.Sdk.
  • A purpose-built collector SDK: readings are batched every 20 s. While the database is unreachable they are buffered on disk and replayed in order. The SDK also owns the heartbeat and hot-reloads configuration through PostgreSQL LISTEN/NOTIFY.
  • A database-backed command queue for talking to devices — opening doors, arming intrusion, PTZ, writing set-points. It replaces the legacy named pipes and lets the API and the collectors live on different machines.
  • Real time end to end: a PostgreSQL trigger fires NOTIFY, the API listens, SignalR pushes to the browser, and the browser invalidates the matching TanStack Query caches.

Authentication & security

  • Passwords hashed with Argon2id (PHC string format), with account lockout after repeated failures.
  • Server-side sessions in an HttpOnly cookie, validated against the database on every request, expiring on inactivity and revocable on demand.
  • User-selectable 2FA: email, SMS or authenticator app (TOTP with QR enrolment), plus recovery codes.
  • CSRF protection (antiforgery via the X-XSRF-TOKEN header) and per-IP rate limiting.
  • Per-area and per-site permissions, with user groups, user impersonation, and an audit log of every action down to the changed fields.
  • Secrets encrypted with ASP.NET Data Protection — device passwords, PINs, SMTP credentials and TOTP secrets. The key ring lives in the database, protected by a certificate; secrets are never returned to the client.
  • Password recovery and invitations via single-use links, and a maintenance mode with an IP allow-list.
  • Uploads validated by type and size, SVG rejected, served with nosniff.

Technical highlights

17.4Mrows migrated in 6.5 min
0diffs on migration validation
~25×time-series compression
20 ssampling interval
  • Time series at scale: 20 s sampling, roughly 25× compression (≈ 4.8 bytes per sample), 15-minute and 1-hour aggregates kept forever, and two years of raw data. Queries pick their source from the requested range — raw, 15 min, 1 h, or the daily rollup table.
  • Time zones done properly: customers span different zones, including half-hour offsets (+05:30). Days, months and schedules are computed in each site's own zone, with tests covering DST transitions.
  • Alarm engine: thresholds evaluated every 2 s, offline-equipment detection, and suppression windows. Email and SMS notifications go out through an outbox with retries and backoff, and delivery is safe across multiple Workers using FOR UPDATE SKIP LOCKED.
  • Video in the browser over WebRTC (WHEP), with the API acting as the broker that enforces per-site permissions.
  • Reporting with 10 block types (charts, KPIs, MTTA, availability, consumption), scheduled in the customer's time zone and delivered as PDF by email.
  • Legacy migration: an importer that reads MySQL directly or straight from a mysqldump file, loading through binary COPY. Imports are idempotent — re-running never duplicates. A real dry run moved 17.4M records (24.5M points) in 6.5 minutes, and sensor-by-sensor, day-by-day validation came back with zero differences. A cutover runbook ships with it.
  • Industrial collectors for SNMP and Modbus running as Windows Services, covering every numeric format and byte order, and grouping registers into block reads.
